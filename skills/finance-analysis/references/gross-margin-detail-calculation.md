# 毛利率明细计算规则

## 数据获取规范

成本明细分析依赖取数工具（`boda` MCP 服务）返回的单位成本结构、投入产出和存货明细等查询结果文件。其中**存货明细文件数据量可能非常庞大**，必须遵循以下规范：

**严禁**：
- ❌ 使用 `cat`、`Read` 等工具完整读取大体积的存货明细原始数据文件
- ❌ 将存货明细文件完整内容加载到上下文中进行分析

**必须**：
- ✅ 优先使用本章节内置脚本（`analyze_margin_detail.py`、`analyze_cost_structure.py`）提取所需数据
- ✅ 如需查看存货明细文件结构，仅读取前 `N` 行样例数据（如 `head -20`）
- ✅ 如需从存货明细中筛选特定数据，使用命令行工具（`jq`、`grep`、`awk`）或 Python 脚本处理，而非直接读取完整文件

## 内置计算脚本

**强制：必须优先使用内置脚本，严禁未确认内置脚本能力前就自己写脚本分析。**
下列脚本已覆盖取数探查、单层明细、成本项目标准占比等绝大多数场景。只有当内置脚本确实缺少所需能力时，才允许手写脚本，且需先说明内置脚本缺什么、为何手写；手写部分不得重复内置脚本已实现的逻辑。

### 数据探查脚本

`inspect_finance_data.py` 用于取数后快速查看数据结构，替代直接 `cat` 读取大文件。

```bash
# 自动识别数据类型，输出字段、记录数、分布汇总
python3 <skill>/scripts/inspect_finance_data.py ucs.json
python3 <skill>/scripts/inspect_finance_data.py io.json
python3 <skill>/scripts/inspect_finance_data.py ledger.json

# 过滤指定物料
python3 <skill>/scripts/inspect_finance_data.py io.json --material 410141198
python3 <skill>/scripts/inspect_finance_data.py ledger.json --material 110140009 --limit 5
```

| 模块 | 输出内容 |
|------|----------|
| 单位成本 | 字段列表、记录数、订单概览（产量/成本/单价/毛利率） |
| 投入产出 | 工段分布、物料分布、核算要素分布、样例行 |
| 存货明细 | 物料分布、会计期间分布、单据类型分布、样例行 |

### 单层明细分析脚本

`analyze_margin_detail.py` 用于查看单个订单和一次性投入产出的明细。

```bash
# 输出全部分析（默认）

# 只输出单位成本结构和成本占比
python3 <skill>/scripts/analyze_margin_detail.py ucs.json --summary

# 输出单位成本结构 + 投入产出分组分析
python3 <skill>/scripts/analyze_margin_detail.py ucs.json input-output.json --io

# 输出单位成本结构 + 投入产出 + 存货价格分析
python3 <skill>/scripts/analyze_margin_detail.py ucs.json input-output.json ledger.json --all

# 只输出异常识别汇总
python3 <skill>/scripts/analyze_margin_detail.py ucs.json input-output.json ledger.json --anomaly
```

| 模块 | 输出内容 |
|------|----------|
| `--summary` | 经营结果、毛利率评级、毛利/毛利率/单位成本校验、成本结构占比及阈值判断 |
| `--io` | 投入产出按生产阶段和核算要素分组汇总、生产阶段净成本、缺失阶段标记、下一层材料编码、负数量/负金额/高占比异常 |
| `--price` | 存货月度加权均价、最高/最低价、期间环比变化、单据类型分布、异常高价单据 |
| `--anomaly` | 低毛利/亏损、成本结构偏高/偏低、数据一致性异常汇总 |

### 成本项目标准占比脚本

`analyze_cost_structure.py` 专门用于"成本项目标准占比"分析，按生产阶段净成本口径剔除下一层产成品/半成品，再把各阶段本阶段费用累计到五大成本项目。

**注意**：该脚本在链路断裂时使用 `last_scale` 直接取值兜底，可能因多产品共用工段数据导致高估。如需准确的逐级展开，优先使用 `analyze_margin_detail.py --summary`。

```bash
# 传入单位成本结构 + 一次性投入产出文件
python3 <skill>/scripts/analyze_cost_structure.py ucs.json --io input-output.json

# 同一订单有多个包装成品时，可只分析指定包装成品
python3 <skill>/scripts/analyze_cost_structure.py ucs.json \
  --material 416102832 \
  --io input-output.json
```

| 模块 | 输出内容 |
|------|----------|
| 阶段净成本 | 每个生产阶段的投入产出总额、剔除下一层金额、本阶段净成本、占完工成本比例 |
| 成本项目标准占比 | 五大成本项目的累计金额、占完工成本比例、阈值判断 |
| 成本项目明细来源 | 每个成本项目来自哪些阶段和核算要素 |
| 生产阶段取数状态 | 包装/缝制/染色/织造/原材料分别标记已取到/未取到/直接取值 |
| 负数/冲销记录 | 负金额或负数量记录 |

### 多链路直接取值规则

上游工段缺失时按以下规则处理：

| 缺失阶段 | 直接取值的下一层 | 受影响的下游 | 兜底机制 |
|----------|------------------|--------------|----------|
| 染色 | 织造 | 原材料 | 织造标"直接取值"、折算系数 = last_scale；原材料保持"已取到"但按 last_scale 兜底 |
| 缝制 | 染色 | 织造、原材料 | 染色标"直接取值"；织造/原材料按 last_scale 兜底 |
| 织造 | 原材料 | - | 原材料标"直接取值"、折算系数 = last_scale |
| 包装 | - | 缝制/染色/织造/原材料 | 所有下游按 last_scale 兜底；报告顶部提示"投入产出无包装成品明细" |

**关键规则**："直接取值"只对**直接父级为"未取到"的工段**使用，不级联到更下游；更深层工段仍标"已取到"，但通过 `last_scale` 兜底按 `stage_total × last_scale` 归集。`last_scale` 为断裂前最后一个有效折算系数。

生产阶段取数状态分四种：

| 状态 | 含义 |
|------|------|
| 已取到 | 该工段有数据，且能正常按父级折算 |
| 直接取值 | 该工段有数据，但**直接父级工段未取到**，折算系数 = last_scale |
| 未取到 | 该工段无数据，可能为委外生产或报表未返回该阶段 |
| 已取到（last_scale 兜底） | 该工段有数据，但**上游链路断裂**导致无父级折算，按 last_scale 兜底计入 |

## 折算率计算规则

各阶段净成本的折算遵循**"上级 carry 金额 ÷ 本工段 stage_total"**原则，链路断裂时使用 `last_scale` 兜底。

### 正常链路

| 阶段 | 折算系数公式 | 说明 |
|------|-------------|------|
| 包装 | **1.0000** | 包装成品为根节点，不做折算 |
| 缝制 | 包装中缝制成品 carry 金额 / 缝制工段投入产出总额 | 上级 carry 金额 ÷ 本工段总额 |
| 染色 | 缝制中毛坯 carry 金额 / 染色工段投入产出总额 | 上级 carry 金额 ÷ 本工段总额 |
| 织造 | 染色中白坯 carry 金额 / 织造工段投入产出总额 | 上级 carry 金额 ÷ 本工段总额 |
| 原材料 | 织造中白坯/毛坯 carry 金额 / 原材料工段投入产出总额 | 上级 carry 金额 ÷ 本工段总额 |

### 链路断裂时

当上游工段缺失时，断裂点下游所有工段统一使用 **last_scale** 作为折算系数：

```
last_scale = 断裂前最后一个有效折算系数（即断裂点前一级的折算系数）

下游工段折算后金额 = 下游工段 stage_total × last_scale
```

| 场景 | 折算系数取值 | 示例 |
|------|-------------|------|
| 染色缺失 | 织造、原材料均使用 `last_scale = 缝制折算系数` | 缝制折算率 0.1099 → 织造/原材料均按 0.1099 |
| 缝制缺失 | 染色、织造、原材料均使用 `last_scale = 包装折算系数（即 1.0）` | 染色/织造/原材料均按 1.0 |
| 织造缺失 | 原材料使用 `last_scale = 染色折算系数` | 原材料按染色折算率 |

### 折算率的业务含义

折算率表示**上级包装成品对下游各工段成本的"认领比例"**。例如：

- 缝制折算率 0.1099 表示：缝制工段总成本中，仅有 10.99% 归因于当前这个包装成品（其余由同订单其他产品或共用产能分摊）
- 织造折算率 0.1099 表示：织造工段总成本中，当前产品认领 10.99%

报告必须在"折算率计算规则"小节中逐条列出每个阶段的计算公式和结果，让用户能复核数据来源。

## 辅助计算工具

临时检查时可使用 `jq`、`awk`、`bc` 或 Python 验证金额、数量、单价和比率。

**财务返回数据的字段几乎全是中文**，使用 `jq` 时必须遵守中文字段写法规范，详见 [jq 中文字段使用指南](jq-chinese-fields-guide.md)。核心要点：

- 中文字段必须使用 `.["字段名"]`，不能用 `.字段名` 简写
- 对象字面量的中文 key 必须加双引号
- 数值字段统一加 `// "0" | tonumber` 防空值
- jq 表达式用单引号包裹，避免 Shell 转义问题

### 替代工具

复杂查询**先确认内置脚本（`analyze_margin_detail.py`、`analyze_cost_structure.py`、`inspect_finance_data.py`）无法完成**，再用以下 Python/jq 方式，且只补内置脚本未覆盖的部分：

```bash
# Python 单行调用
python3 -c "
import json
data = json.load(open('input-output.json'))['data']
rows = [r for r in data if r.get('所属工段') == '原材料']
total = sum(float(r.get('金额') or 0) for r in rows)
print(f'原材料金额: {total:,.2f} 元，行数 {len(rows)}')
"

# 数字验算
echo "scale=4; 16400 / 100" | bc                 # 完工成本 / 完工产量 = 单位成本
awk 'BEGIN{printf "%.4f\n", 3600/20000*100}'      # 毛利率 = 毛利/收入
```

数字验算优先 `bc -l` 保精度；简单对比用 `awk`；复杂分组、回归改用 Python。

## 成本项目标准占比

**成本结构占比必须以投入产出数据为基础逐级展开**，严禁使用单位成本字段中的下游工段合并金额反推。单位成本仅包含包装层自身字段，下游工段金额全部合并在"未分类"中，无法用于标准占比分析。

以订单完工成本作为分母。若只能取得完工成本，报告中明确说明"占比以完工成本为分母"。

| 成本项目 | 预设标准占比 | 正常区间 | 计算逻辑 |
|----------|--------------|----------|----------|
| 原材料 | 30% | 25% - 35% | 原材料阶段金额（原料/纱线等）+ 织造阶段原料类金额，按折算系数累加 |
| 辅料（缝制 + 包装） | 10% | 5% - 15% | 包装辅料 + 缝制辅料 + 公共辅料等，按折算系数累加 |
| 直接人工 | 35% | 30% - 40% | 各阶段直接人工/间接人工/福利费/五险一金/劳务费，按折算系数累加 |
| 制造费用 | 20% | 15% - 25% | 各阶段折旧费/水电费/修理费/低值易耗品/汇总其他，按折算系数累加 |
| 外协加工费 | 5% | 0% - 10% | 各阶段加工费/委外加工费，按折算系数累加 |

### 投入产出口径逐级展开算法

1. **索引**：按 `物料编码` 建立 io 行索引。
2. **追溯起点**：以单位成本中的 `物料编码`（包装成品）为 root_code。
3. **逐段遍历**：按 包装 → 缝制 → 染色 → 织造 → 原材料 顺序遍历：
   - 当前工段行 = `rows_by_material[current_materials]` 中 `所属工段 == 当前工段` 的行。
   - 若当前工段无数据 → 链路断裂，后续工段使用 `last_scale` 兜底，取全量数据。
   - 包装阶段折算系数 = 1.0。
   - 非包装阶段折算系数 = 上级 carry 金额 / 本工段 stage_total。
   - carry 行（下一层半成品）提取 `材料编码` 作为下一阶段的 `current_materials`。
4. **成本归集**：对每个工段的非 carry 行：
   - 金额 = 原始金额 × 折算系数。
   - 按 `核算要素名称` 映射到五大成本项目（原材料 / 辅料 / 直接人工 / 制造费用 / 外协加工费）。
   - **carry 行不计入任何成本项目**，它们代表向下游转移的价值。
5. **未追溯半成品**：
   ```
   未追溯半成品 = 完工成本 - Σ(五大成本项目金额)
   ```
   反映因数据缺失未能展开到成本项目的金额。各项目之和必须等于完工成本。

### 默认分类映射

| 分析分类 | 投入产出核算要素（按名称关键词匹配） |
|----------|--------------------------------|
| 原材料 | 原料、纱线、其他原料；`所属工段 = 原材料` 的行全部归入原材料 |
| 辅料 | 包装辅料、缝制辅料、公共缝制辅料、公共包装辅料 |
| 直接人工 | 直接人工、间接人工、福利费、五险一金、劳务费 |
| 制造费用 | 折旧费、水费、电费、水电费、修理费、低值易耗品领用摊销、汇总其他 |
| 外协加工费 | 加工费、委外加工费 |
| 半成品/产成品链路 | 缝制成品、毛坯、白坯、坯布（carry 行，不计入成本项目） |

如果字段分类存在歧义，必须在报告中单列"未分类/待确认成本"，不要强行归类。

`所属工段 = 原材料` 的行默认全部归入"原材料"成本项目，不参与织造阶段的成本归集。

## 毛利率分级评估

| 毛利率范围 | 评级 | 说明 |
|-----------|------|------|
| >= 30% | 优秀 | 利润空间充足 |
| 20% ~ 30% | 良好 | 利润水平正常 |
| 10% ~ 20% | 一般 | 利润空间偏紧，需关注成本控制 |
| 0% ~ 10% | 预警 | 利润较低，建议分析成本构成 |
| < 0% | 异常 | 亏损订单，需重点排查原因 |

以上为参考阈值，实际判断应结合行业和企业的标准。

## 基础计算规则

- 毛利 = 销售无税金额 - 完工成本。与返回字段毛利不一致时，列为数据校验差异。
- 毛利率 = 毛利 / 销售无税金额。与返回字段毛利率(小数)或毛利率不一致时，列为数据校验差异。
- 单位成本 = 完工成本 / 完工产量。与返回字段单位成本不一致时，列为数据校验差异。
- 成本项目占比 = 成本项目金额 / 订单总成本。按阈值判断正常、偏高、偏低。
- 投入产出单位耗量 = 投入产出数量 / 上层完工产量或上层投入产出数量。分母必须说明来源。
- 投入产出单位成本 = 投入产出金额 / 上层完工产量或上层投入产出数量。不可用时只展示原始金额、数量、单价。
- 存货价格影响 = 当前材料单价与同期间均价、最高价、最低价或上一期间可比单价对比。没有可比期间数据时，只说明本期价格分布。
- 价格波动影响金额 = (实际单价 - 均价) × 消耗数量。用于量化单价波动对订单成本的影响。

数值处理：优先使用脚本或工具验证；报告中保留足够小数位并标明四舍五入展示。
