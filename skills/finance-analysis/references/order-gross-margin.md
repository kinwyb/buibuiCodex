## 数据获取

使用 `boda` MCP 服务的 **`finance_analysis`** 工具查询订单成品毛利率数据。

### 调用示例

参数以 JSON 传入：

```jsonc
// 1. 查询默认会计区间的全部订单毛利率（未指定区间时不传 startPeriod/endPeriod）
{}

// 2. 按订单号筛选，未指定会计区间时同样不要传 startPeriod/endPeriod
{ "orderCode": "订单号1,订单号2" }

// 3. 用户明确指定会计区间时，才传 startPeriod/endPeriod
{ "startPeriod": "2026-04", "endPeriod": "2026-06" }

// 4. 查询越南组织
{ "org": "越南" }
```

## 参数说明

| 参数 | 必填 | 默认值 | 说明 |
|------|------|--------|------|
| `startPeriod` | ❌ | 工具默认 | 开始会计区间(yyyy-MM)，仅用户明确指定区间时传入 |
| `endPeriod` | ❌ | 工具默认 | 结束会计区间(yyyy-MM)，仅用户明确指定区间时传入 |
| `orderCode` | ❌ | - | 订单号，多个用逗号分隔 |
| `org` | ❌ | 义乌 | 组织信息，可选值：`义乌`、`越南` |

### 会计区间格式

格式为 `yyyy-MM`，例如 `2026-04`。

如果用户未明确财务区间/会计区间，调用工具时不要传 `startPeriod` 和 `endPeriod`，由工具使用默认区间；不要自行按当前日期计算月份。只有用户明确给出区间时，才按用户提供的 `yyyy-MM` 值传入。

## 输出格式

工具返回 **JSON** 格式：

```json
{
  "columns": ["字段名1", "字段名2", ...],
  "data": [
    {"字段名1": "值1", "字段名2": "值2", ...},
    ...
  ]
}
```

- `columns`：字段名列表，定义数据含义及读取顺序
- `data`：数据数组，每个元素为一条订单记录
- 空字符串 `""` 表示该字段无数据

## 数据字段说明

`columns` 中列出了所有可用字段。常见字段包括（实际字段以工具返回为准）：

| 分类 | 常见字段 | 说明 |
|------|----------|------|
| **订单标识** | 订单号、客户、物料编码、物料名称 | 订单和产品标识信息 |
| **订单属性** | 订单类型、销售渠道类型、销售部门 | 订单的业务属性 |
| **金额信息** | 销售单价(无税)、销售无税金额、成本单价、成本金额 | 订单金额及成本数据 |
| **毛利率** | 毛利率、毛利率(小数)、毛利 | 核心利润指标 |
| **数量信息** | 产量 | 订单产量 |
| **时间信息** | 会计期间 | 财务归属期间 |

> 注意：实际返回字段以工具返回的 `columns` 为准，上表仅为常见字段参考。

## 内置统计脚本

提供 `scripts/analyze_margin.py` 用于毛利率统计分析，避免每次重复编写脚本。

### 脚本用法

```bash
# 全部分析（默认，等同 --all）
python3 <skill>/scripts/analyze_margin.py data.json

# 仅输出总览统计
python3 <skill>/scripts/analyze_margin.py data.json --summary

# 仅输出毛利率分布
python3 <skill>/scripts/analyze_margin.py data.json --tier

# 仅输出亏损订单明细
python3 <skill>/scripts/analyze_margin.py data.json --loss

# 仅输出低毛利订单明细
python3 <skill>/scripts/analyze_margin.py data.json --low

# 按订单号汇总
python3 <skill>/scripts/analyze_margin.py data.json --group-by-order

# 按物料名称汇总
python3 <skill>/scripts/analyze_margin.py data.json --group-by-material

# 按客户汇总
python3 <skill>/scripts/analyze_margin.py data.json --group-by-customer

# 按销售部门汇总
python3 <skill>/scripts/analyze_margin.py data.json --group-by-department

# 按销售渠道类型汇总
python3 <skill>/scripts/analyze_margin.py data.json --group-by-channel

# 按订单类型汇总
python3 <skill>/scripts/analyze_margin.py data.json --group-by-order-type

# 从 stdin 读取
cat data.json | python3 <skill>/scripts/analyze_margin.py -

# 组合多个选项
python3 <skill>/scripts/analyze_margin.py data.json --summary --loss --group-by-customer
```

### 脚本输出说明

| 选项 | 输出内容 |
|------|----------|
| `--summary` | 订单总数、有效记录数、涉及客户数、涉及销售部门数、销售总额、成本总额、毛利总额、加权/算术平均毛利率、亏损订单数及占比、最高/最低毛利率订单（含客户信息） |
| `--tier` | 按毛利率分级（≥30%优秀、20%-30%良好、10%-20%一般、0%-10%预警、<0%异常）统计订单数、占比、销售金额、毛利 |
| `--loss` | 毛利率<0的订单明细（按毛利率升序），含订单号、客户、物料、销售部门、产量、销售金额、成本金额、毛利、毛利率，以及亏损合计 |
| `--low` | 毛利率0%-10%的订单明细（按毛利率升序），字段同亏损明细 |
| `--group-by-order` | 按订单号汇总的销售金额、成本金额、毛利、加权毛利率（按加权毛利率升序） |
| `--group-by-material` | 按物料名称汇总的产量、销售金额、成本金额、毛利、加权毛利率（按加权毛利率升序） |
| `--group-by-customer` | 按客户汇总的销售金额、成本金额、毛利、加权毛利率（按加权毛利率升序） |
| `--group-by-department` | 按销售部门汇总的销售金额、成本金额、毛利、加权毛利率（按加权毛利率升序） |
| `--group-by-channel` | 按销售渠道类型汇总的销售金额、成本金额、毛利、加权毛利率（按加权毛利率升序） |
| `--group-by-order-type` | 按订单类型汇总的销售金额、成本金额、毛利、加权毛利率（按加权毛利率升序） |

### 使用流程

```bash
# 1. 调用 finance_analysis 工具取数，并将返回的 JSON 原样写入 margin_data.json

# 2. 使用内置脚本分析
python3 <skill>/scripts/analyze_margin.py margin_data.json

# 3. 基于脚本输出进行深度分析（见下文"分析方法"和"异常识别"）
```

## 分析方法

### 步骤1：运行内置脚本获取基础统计

使用 `analyze_margin.py` 快速获取数据全貌，避免手动计算。

**注意**：内置脚本基于常见字段设计。由于取数工具返回的数据字段可能发生变更或新增，如果用户需求的数据维度不在脚本覆盖范围内（如需要按新增字段分组统计），**应自行编写脚本**处理数据，而非强行套用内置脚本。编写脚本时须遵循通用规则中的数据真实性和计算精度要求。

### 步骤2：毛利率计算验证

毛利率 = (销售收入 - 销售成本) / 销售收入 × 100%

抽查验证脚本输出的毛利率是否与原始数据一致，特别是：
- 毛利率最高和最低的订单
- 亏损订单
- 毛利率接近阈值的订单（如接近30%、10%、0%）

### 步骤3：异常识别与根因分析

在脚本输出的基础上，结合下文"异常识别"章节进行深入分析：
- 对亏损订单和低毛利订单，分析成本偏高的具体原因
- 检查同一物料在不同订单间的毛利率差异
- 识别成本单价为负等数据异常
- 分析毛利率为空的记录原因

### 步骤4：补充业务洞察

脚本提供数据统计，但需要人工补充：
- 亏损订单可能的原因（原料涨价、工艺复杂、定价过低、产量过小等）
- 低毛利订单是否需要调整定价或优化成本
- 高毛利订单是否可持续
- 不同物料/客户的毛利率分布特征

### 毛利率分级评估（脚本内置阈值）

| 毛利率范围 | 评级 | 说明 |
|-----------|------|------|
| ≥ 30% | 优秀 | 利润空间充足 |
| 20% ~ 30% | 良好 | 利润水平正常 |
| 10% ~ 20% | 一般 | 利润空间偏紧，需关注成本控制 |
| 0% ~ 10% | 预警 | 利润较低，建议分析成本构成 |
| < 0% | 异常 | 亏损订单，需重点排查原因 |

> 以上为参考阈值，实际判断应结合行业和企业的标准。

## 异常识别

重点关注以下风险信号：

### 亏损订单（毛利率 < 0）

- 毛利率 < 0 的订单，需重点分析亏损原因
- 关注销售成本是否异常偏高
- 检查是否为小批量订单（产量小导致单位成本高）
- 检查成本单价是否为负数（数据异常）
- 分析亏损金额大小，区分严重亏损和轻微亏损

**常见原因**：
- 原材料成本上涨但售价未调整
- 订单量过小，固定成本分摊过高
- 工艺复杂导致人工成本高
- 定价策略问题（战略性亏损或定价错误）

### 低毛利订单（毛利率 0% ~ 10%）

- 毛利率持续低于 10% 的订单
- 同一客户多个订单毛利率均偏低
- 同一物料在不同订单中毛利率都偏低
- 低毛利但销售金额大的订单（虽然毛利率低但绝对金额可能可观）

**关注点**：
- 是否有优化空间（降低成本或调整定价）
- 是否为战略性产品（引流产品、竞争产品）
- 是否影响整体利润率

### 毛利率波动

- 同一款号/物料在不同订单间毛利率差异较大（如>10个百分点）
- 同一客户不同期间毛利率波动明显
- 检查是否为产量差异导致（规模效应）
- 检查是否为原材料批次成本差异

**分析维度**：
- 按物料汇总，查看同一物料的毛利率分布
- 按客户汇总，查看同一客户的毛利率稳定性
- 按时间区间对比，查看趋势变化

### 数据完整性问题

- 关键字段（订单号、毛利率）为空的记录
- 订单金额为 0 的记录（可能是异常数据）
- 毛利率字段为空（脚本会标注无效记录数）
- 成本金额或销售金额为空

**处理方式**：
- 标注无效记录数量
- 分析是否为数据导出问题
- 在分析报告中说明数据质量情况

### 成本单价异常

- 成本单价为负数：明显的数据异常，需标注并排查
- 成本单价远高于销售单价：导致毛利率为负，需分析原因
- 成本单价波动过大：同一物料在不同订单中成本单价差异巨大

### 产量异常

- 产量极小的订单（如<100）：单位成本可能偏高，毛利率低可能是正常的
- 产量与订单金额不匹配：检查是否为数据错误

### 高毛利率异常

- 毛利率 > 100%：数据异常（销售金额 > 成本金额 + 销售金额不合理）
- 毛利率接近100%：检查成本是否被低估
- 毛利率显著高于同类物料：需分析原因（是否为定价优势或成本计算错误）

### 数据一致性检查

- 销售无税金额 ≈ 销售单价(无税) × 产量
- 成本金额 ≈ 成本单价 × 产量
- 毛利 ≈ 销售无税金额 - 成本金额
- 毛利率(小数) ≈ 毛利 / 销售无税金额

如发现不一致，需标注并分析原因（四舍五入误差、数据导出问题等）。
