# 财务分析

## 数据获取方式（boda MCP 服务）

本技能的数据**全部通过 `boda` MCP 服务提供的工具获取**。

| 数据 | MCP 工具 | 后端报表 |
|------|----------|----------|
| 综合毛利率 | `finance_analysis` | 101190.综合毛利率查询 |
| 单位成本结构 | `finance_analysis_unitCostStructure` | 101191.单位成本结构 |
| 投入产出表 | `finance_analysis_inputOutput` | 101192.投入产出表 |
| 存货明细帐 | `finance_analysis_inventoryLedger` | 101193.存货明细帐 |

- 通过 MCP 工具调用方式调用上述工具，参数以 JSON 传入；各工具的参数说明见 `references/` 中对应文档
- 工具返回 **JSON** 格式数据（结构为 `{"columns": [...], "data": [{...}]}`）
- **无需再传 userid**：身份认证与组织权限由 MCP 服务端统一处理
- 需要将数据保存为本地文件时（如内置脚本分析所需的 `margin_data.json`、`ucs.json`），**将工具返回的 JSON 原样写入指定文件**

## 功能列表

| 功能 | 说明 | 参考文档 | 状态 |
|------|------|----------|------|
| 订单毛利率分析 | 查询指定会计区间的订单成本毛利率数据 | `references/order-gross-margin.md` | ✅ 可用 |
| 毛利率明细分析 | 基于单位成本结构、投入产出和存货明细帐分析订单成本组成、异常原因与优化建议 | `references/gross-margin-detail.md` | ✅ 可用 |

> 本技能支持扩展，后续可在此表中增加新的财务分析功能，每个功能对应一个 references 文档。

## 功能选择规则

- 默认使用“订单毛利率分析”：用户只说分析毛利率、成本、利润、订单利润、财务区间、低毛利、亏损、报价风险，或只提供订单号要求分析时，先读取 `references/order-gross-margin.md`，查询订单毛利率数据并输出整体经营结果、低毛利/亏损风险和简要建议。
- 只在用户明确要求“成本组成”“成本明细”“毛利率明细”“单位成本结构”“投入产出”“存货明细”“材料价格影响”“耗量分析”“生产环节成本拆分”“阶段净成本”“成本项目标准占比”等细项时，读取 `references/gross-margin-detail.md` 并执行毛利率明细分析。
- 订单毛利率分析发现低毛利或亏损时，可以建议用户继续分析成本明细，但不要自动切换到毛利率明细分析，除非用户明确同意或原始请求已经要求明细。

## 通用规则

### ⚠️ 优先使用内置脚本（强制）

本技能 `scripts/` 目录已提供经过验证的分析脚本，覆盖绝大多数取数、汇总、占比、异常识别和成本结构测算需求。**必须优先使用内置脚本，严禁一上来就自己写脚本分析。**

可用内置脚本（用法详见对应 references 文档）：

| 脚本 | 用途 | 参考文档 |
|------|------|----------|
| `analyze_margin.py` | 订单毛利率统计、分档、亏损/低毛利筛选、按订单分组 | `references/order-gross-margin.md` |
| `inspect_finance_data.py` | 取数后快速查看数据结构、字段、分布，替代 `cat` 读大文件 | `references/gross-margin-detail-calculation.md` |
| `analyze_margin_detail.py` | 单订单单位成本结构、投入产出分组、存货价格、异常识别 | `references/gross-margin-detail-calculation.md` |
| `analyze_cost_structure.py` | 成本项目标准占比、阶段净成本、生产阶段取数状态 | `references/gross-margin-detail-calculation.md` |

**强制执行流程**：

1. 接到分析任务后，**先查上表确认是否有内置脚本能完成**，有则直接调用，不要自己写脚本。
2. 内置脚本的输出若已满足需求，**直接基于其结果分析，不得再额外写脚本重复计算**。
3. 只有当内置脚本确实无法满足需求时（如脚本无对应参数、需要全新的跨文件统计维度），才允许手写脚本，且**必须先向用户说明：内置脚本缺少什么能力、为什么需要手写**。
4. 手写脚本只能用于内置脚本未覆盖的那部分，**禁止重写内置脚本已实现的逻辑**。

**严禁**：
- ❌ 不查内置脚本就直接用 Python 手写完整分析流程
- ❌ 内置脚本能跑出结果，却再写脚本做同样的汇总/占比/校验
- ❌ 用「自己写的更灵活」为由绕过内置脚本

### ⚠️ 数据真实性要求（强制）

**所有分析结论必须严格基于 `boda` MCP 工具返回的实际数据。**

**严禁**：编造数据、推测缺失字段、对不存在的字段进行分析。

**必须**：只分析实际返回数据、标注缺失字段、查询无结果时明确告知用户。

**字段发现**：
- 当用户提到的字段在 skill 描述中未列出时，**先执行查询获取数据**，检查实际返回中是否包含该字段
- 如果数据中存在该字段：按用户要求处理并给出结果
- 如果数据中也不存在：**严禁编造或猜测**，明确告知用户该字段在当前数据中不存在，并列出实际可用字段

### ⚠️ 数字计算精度要求（强制）

财务数据对准确性要求极高，**所有数值计算必须精确，禁止估算或四舍五入后作为准确值呈现。**

**严禁**：
- ❌ 对数值进行估算、四舍五入后不加说明直接呈现
- ❌ 跳过计算直接给出"大概"、"大约"等模糊数值
- ❌ 手动心算复杂计算而不验证

**必须**：
- ✅ 所有加减乘除计算必须逐步精确完成，不可跳步
- ✅ 引用原始数据中的数值必须与返回结果完全一致，逐字核对
- ✅ 如需估算（如占比、趋势推断），数值前**必须标注**「约」「≈」「估算」等字样，与精确值明确区分
- ✅ 涉及金额、毛利率等关键指标的计算，优先使用工具（如 bc、awk）验证，避免浮点精度问题

### ⚠️ 跨时间对比表述规范（强制）

对比不同月份或时间段的数据时，**结果必须以时间顺序为前提，先描述早期数据，再描述后期数据，体现趋势走向。**

**严禁**（先说后期再说早期，颠倒时间顺序）：
- ❌ "3月整体毛利率仅 3.66%，远低于4月的 17.83%，利润状况显著恶化。"

**必须**（按时间从早到晚叙述，体现趋势变化）：
- ✅ "3月整体毛利率仅 3.66%，利润状况严重恶化，4月已明显改善至 17.83%。"
- ✅ "从3月的 3.66% 提升至4月的 17.83%，毛利率改善 14.17 个百分点。"

**原则**：始终按「早期 → 后期」的顺序描述，用"提升/改善/恶化/下降"等趋势词汇连接，而非倒叙对比。

### ⚠️ 权限错误处理（强制）

当取数工具返回权限相关错误时，**立即停止，禁止重试**。

权限错误关键词：`无权操作`、`权限不足`、`无权限`、`unauthorized`、`forbidden`、`token 失败`。

遇到权限错误：立即停止 → 将错误信息原样返回 → 提示用户检查 MCP 服务授权状态与账号数据权限。

**严禁**：变换参数反复重试、编造数据。

### ⚠️ jq 中文字段访问要求（强制）

财务返回数据几乎全部字段都是中文（`订单号`、`所属工段`、`核算要素名称`、`金额` 等），使用 `jq` 抽取、汇总、过滤时**必须使用 `.["字段名"]` 写法**：

**严禁**（jq 不支持中文标识符简写，会报 syntax error）：
- ❌ `.订单号` `.所属工段` `.["金额"] // 0` 中 `.金额` 形式的字段简写
- ❌ `.毛利率(小数)` `.单位成本(无税)` 等带括号字段用点号
- ❌ 在脚本中省略引号直接拼中文键

**必须**：
- ✅ 所有中文字段、带括号字段、含特殊符号字段统一用 `.["字段名"]`
- ✅ Shell 中必须用双引号包裹 jq 表达式，避免 `$`、空格、中文被拆分
- ✅ 数字字段取数统一加 `// "0" | tonumber` 防空值报错
- ✅ 中文输出配合 `jq -r` / `--raw-output` 保留中文
- ✅ 临时检查前先 `head -1 file.json | jq .` 验证 JSON 能正常解析、字段名拼写正确

完整模板、错误示范、替代工具见 `references/jq-chinese-fields-guide.md`。

## 使用方法

1. 根据用户请求，从功能列表中找到对应功能
2. 阅读对应的 references 文档，了解取数工具、内置脚本和分析方法
3. 获取必要参数（如订单号、物料编码等）；会计区间只有用户明确指定时才传入工具
4. 调用对应 MCP 工具取数，必要时将返回 JSON 写入本地文件，再按文档中的分析流程进行分析
5. 输出分析报告

## 注意事项

- 如果用户未明确财务区间/会计区间，调用工具时不要传 `startPeriod` 和 `endPeriod`，由工具使用默认区间；不要自行按当前日期计算月份。
- 工具调用失败时检查 MCP 服务是否已连接/授权，以及网络是否可连通 boda 服务
- **遇到权限相关错误时立即停止，禁止重试**
- **分析结论必须完全基于实际返回数据，禁止编造或推测**
