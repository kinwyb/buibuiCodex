# 订单技能集

本技能集提供订单分析相关的多种功能模块，便于后续扩展。本文档内容必须完整读区分析其中的专业术语说明以及共公的异常处理方式

## 可用模块

| 模块 | MCP 工具 | 文件 | 功能描述 |
|------|----------|------|----------|
| **生产进度分析** | `order_process` | [references/production-progress.md](references/production-progress.md) | 分析订单生产流程进度，识别交期风险、工序瓶颈、数据异常等隐患 |
| **物料使用率分析（MU）** | `order_mu` | [references/material-use.md](references/material-use.md) | 分析织、染、缝各环节物料损耗，计算材料利用率，评估投料控制 |
| **生产效率分析** | `order_efficiency` | [references/efficiency.md](references/efficiency.md) | 按日期、部门、员工查询生产效率，分析工时产出、效率趋势与异常 |

> 💡 后续将增加更多订单相关功能模块

## 数据获取方式（boda MCP 服务）

本技能的数据**全部通过 `boda` MCP 服务提供的工具获取**。

### 调用方式

- 通过 MCP 工具调用方式调用 `boda` 服务的对应工具（`order_process` / `order_mu` / `order_efficiency`），参数以 JSON 传入
- 各工具的参数说明见对应模块文档（`references/` 目录）
- 工具返回 **JSON** 格式数据（结构为 `{"columns": [...], "data": [{...}]}`），分析必须基于返回内容本身
- **无需再传 userid**：身份认证与组织权限由 MCP 服务端统一处理

### 数据落盘（按需）

需要将数据保存为本地文件时（例如效率分析生成图表），**根据工具返回判断是将的 JSON 原样写入指定文件还是按提示下载完整数据**即可：

```
将 order_efficiency 返回的 JSON 内容写入 ./efficiency_data.json
```

同一份数据只应获取一次，报告分析与图表生成共用同一份 JSON 文件。

## ⚠️ 重要术语说明

### 回染

"回染"是生产流程中的一个工序节点，含义是：**染色部门完成染色后，将布匹发回给缝制部门（即"回"到缝制）**。

**"回染"绝对不是"重新染色"或"再次染色"的意思。** 它不是次品、不是返工，而是正常的生产流转步骤。

**严禁**以下理解：
- ❌ 将"回染"理解为"重新染色"或"二次染色"
- ❌ 将"回染数"计入次品数或返工数
- ❌ 将"回染"相关数据作为质量异常的依据

**正确**理解：
- ✅ "回染" = 染色完成后发回给下一工序，是正常的工序流转
- ✅ "回染数" = 已完成染色并发出的数量，属于进度数据，不是质量数据
- ✅ 在明细数据中，"发染数"是送去染色的数量，"回染数"是染色完成发回的数量，"排回染数"是排队等待染色完成发回的数量

## ⚠️ 公共规则（所有模块必须遵守）

### 时间获取要求（强制）

**订单数据对时间极其敏感。** 每次执行分析前，**必须**通过以下方式获取当前准确时间：

```bash
date "+%Y-%m-%d %H:%M:%S"
```

**严禁**以下行为：
- ❌ 使用系统提示中提供的日期作为当前时间（该日期可能不准确）
- ❌ 根据历史对话或记忆推断当前时间
- ❌ 假设或估算当前时间
- ❌ 省略时间获取步骤直接进行分析

**必须**在每次分析开始时**实际执行** `date` 命令，以命令返回结果作为分析基准时间。

### 数据真实性要求（强制）

**所有分析结论必须严格基于 `boda` MCP 工具返回的实际数据。**

**严禁**以下行为：
- ❌ 编造、虚构任何订单号、状态、日期或数值
- ❌ 在数据缺失时自行补充或推测缺失字段的值
- ❌ 对数据中不存在的字段进行分析或评论
- ❌ 将不同订单的数据混淆或张冠李戴

**必须**遵守以下原则：
- ✅ 只分析工具实际返回的数据，字段值必须与原始输出完全一致
- ✅ 如果某字段为空或缺失，在报告中如实标注"数据缺失"或"未提供"
- ✅ 如果查询无结果，明确告知用户"未查询到订单数据"，不做任何推测
- ✅ 引用具体数值时必须与原始数据逐字核对

### 权限错误处理（强制）

**当查询接口返回权限相关错误时，必须立即停止，禁止重试。**

以下关键词表示权限错误：
- "无权操作"、"权限不足"、"无权限"
- "unauthorized"、"forbidden"、"permission denied"、"access denied"
- "token" 相关错误（如 "获取 token 失败"）

**遇到权限错误时必须：**
1. **立即停止**，不再尝试重新调用工具或重试
2. 将完整的错误信息原样返回给用户
3. 提示用户检查 MCP 服务授权状态与账号是否有相关数据权限

**严禁**以下行为：
- ❌ 变换参数反复重试
- ❌ 忽略错误继续分析
- ❌ 编造数据来替代调用失败的结果

### 数据核对步骤（所有模块必须执行）

分析完成后，**必须**执行以下核对流程：

1. 将报告中引用的每个订单号、日期、状态、数值与 MCP 工具返回的原始 JSON 数据逐一比对
2. 检查是否有遗漏的订单（报告中的订单数应与原始 JSON data 数组长度一致）
3. 检查是否有字段值与原始数据不一致的情况
4. 如发现任何不一致，立即修正报告内容
5. 在报告末尾附上核对结论：`数据核对：通过 ✅` 或 `数据核对：已修正 X 处偏差`

## 通用注意事项

- JSON 数据中空字符串 `""` 表示该字段无数据，分析时视为未发生/未填写
- 工具调用失败时检查 MCP 服务是否已连接/授权，以及网络是否可连通 boda 服务
- **遇到权限相关错误时立即停止，禁止重试，将错误信息原样返回给用户**
- **每次分析都必须重新获取当前时间，禁止复用之前的时间**
- **分析结论必须完全基于实际返回数据，禁止编造或推测任何信息**
- **分析完成后必须执行数据核对步骤，确保报告与原始数据一致**
