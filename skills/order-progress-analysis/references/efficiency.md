# 生产效率分析模块

## 概述
本模块用于查询和分析生产系统中员工的生产效率数据，支持按日期、部门、员工维度查询，可输出汇总或明细数据，并生成生产效率柱状图。

## 核心概念

**生产效率** = 产出标准工时 / 上班时间 × 100%

即员工在上班时间内的有效产出比例，衡量生产效率的高低：

```
生产效率 = (产出标准工时(小时) / 上班时间(小时)) × 100%
```

效率越接近或超过 100% 表示产出高效。低于合理范围则表示产能利用不足或存在效率损失。

## 数据获取

使用 `boda` MCP 服务的 **`order_efficiency`** 工具查询生产效率数据。

### 调用示例

参数以 JSON 传入：

```jsonc
// 1. 汇总查询 - 按部门和日期汇总（默认模式）
{ "startDate": "2026-06-16", "endDate": "2026-06-20" }

// 2. 明细查询 - 显示员工级别明细
{ "startDate": "2026-06-16", "endDate": "2026-06-20", "detail": true }

// 3. 指定部门的汇总查询
{ "startDate": "2026-06-16", "endDate": "2026-06-20", "deptNo": "<部门编号>" }

// 4. 指定员工的明细查询
{ "startDate": "2026-06-16", "endDate": "2026-06-20", "detail": true, "employeeNo": "<员工号>" }
```

### 参数说明

| 参数 | 必填 | 默认值 | 说明 |
|------|------|--------|------|
| `startDate` | ✅ | - | 开始日期，格式 `yyyy-MM-dd` |
| `endDate` | ✅ | - | 结束日期，格式 `yyyy-MM-dd` |
| `deptNo` | ❌ | - | 部门编号，用于筛选特定部门 |
| `employeeNo` | ❌ | - | 员工工号，用于筛选特定员工 |
| `detail` | ❌ | false | 是否返回明细信息（员工级别数据） |

### 输出格式

工具返回 **JSON** 格式，结构如下：

```json
{
  "columns": ["字段名1", "字段名2", ...],
  "data": [
    {"字段名1": "值1", "字段名2": "值2", ...},
    ...
  ]
}
```

- `columns`：字段名列表，定义数据含义及读取顺序
- `data`：数据数组，每个元素为一条记录（键值对）
- 空字符串 `""` 表示该字段无数据

### 模块注意事项

- `startDate` 和 `endDate` 为必填参数，必须提供日期范围
- 汇总模式返回**两级汇总数据**，通过 `汇总类型` 字段区分：
  - **大部门汇总**：按大部门+工作日期分组，统计整个成衣一部/二部/三部的效率（`部门` 字段为空）
  - **部门汇总**：按大部门+部门+工作日期分组，统计各缝制小组的效率
- 明细模式（`detail: true`）返回员工级别的原始数据
- `deptNo` 部门筛选在汇总和明细模式下均可使用
- `employeeNo` 员工号筛选通常配合 `detail: true` 明细模式使用
- 产出标准工时为空的记录不参与效率计算

## 大部门映射

汇总模式下，系统根据部门名称前缀自动归类大部门：

| 部门前缀 | 大部门 |
|---------|--------|
| 棒杰* | 成衣一部 |
| 内销* | 成衣二部 |
| 姗娥* | 成衣三部 |
| 其他 | 其他 |

## 数据字段说明

### 汇总数据（默认模式，不加 `-d`）

汇总查询返回**两级汇总数据**，所有记录混合在同一个 data 数组中，分析时应先按 `汇总类型` 字段分组处理：

- **大部门汇总**用于整体评估各成衣部门的效率水平
- **部门汇总**用于细节对比，发现各部门之间的效率差异

| 字段 | 说明 |
|------|------|
| 汇总类型 | 区分记录类型：`大部门汇总` 或 `部门汇总` |
| 大部门 | 按部门前缀归类的上级部门（成衣一部/成衣二部/成衣三部/其他） |
| 部门 | 具体部门名称（大部门汇总时为空字符串 `""`） |
| 工作日期 | 日期，格式 `YYYY-MM-DD` |
| 人数 | 按员工工号去重统计的参与计算员工数 |
| 上班时间(小时) | 该维度当日总上班时间（小时） |
| 产出标准工时(小时) | 该维度当日总产出标准工时（小时） |
| 效率 | 生产效率百分比（产出标准工时/上班时间×100%） |

#### 汇总数据结构示例

| 汇总类型 | 大部门 | 部门 | 工作日期 | 人数 | 上班时间 | 产出标准工时 | 效率 |
|---------|--------|------|----------|------|----------|--------------|------|
| 大部门汇总 | 成衣一部 | | 2026-06-16 | 150 | 1500.50 | 1650.30 | 110.00% |
| 部门汇总 | 成衣一部 | 棒杰缝制一组 | 2026-06-16 | 30 | 300.20 | 330.50 | 110.09% |

### 明细数据（加 `-d` 参数）

返回员工级别的原始数据，主要字段：

| 字段 | 说明 |
|------|------|
| 部门 | 员工所属部门 |
| 工作日期 | 日期 |
| 员工号 | 员工编号 |
| 员工姓名 | 员工姓名 |
| 上班时间(小时) | 该员工当日上班时间（小时） |
| 产出标准工时(小时) | 该员工当日产出标准工时（小时） |

> 注意：明细数据的具体字段以实际返回为准，以上为基于代码的核心字段。如有额外字段（如工序、岗位等），分析时应一并考虑。

## 分析流程

### 第一步：获取当前时间

```bash
date "+%Y-%m-%d %H:%M:%S"
```

### 第二步：一次性获取效率数据并保存

调用 `order_efficiency` 工具获取汇总数据，并**将返回的 JSON 原样写入 `efficiency_data.json`**，后续分析和图表生成复用同一份数据：

```jsonc
// 汇总查询（默认模式，必做一次）
{ "startDate": "<开始日期>", "endDate": "<结束日期>" }
```

如需员工级分析，再调用一次明细查询，并将返回 JSON 写入 `efficiency_detail_data.json`：

```jsonc
// 明细查询（按需）
{ "startDate": "<开始日期>", "endDate": "<结束日期>", "detail": true }
```

如遇到权限相关错误（见 SKILL.md 权限错误处理章节），**立即停止**。

> 重要：效率分析默认只查询一次汇总数据。不要为了生成图表再次调用 `order_efficiency` 工具；报告分析和 `efficiency_chart.py` 都应读取同一个 `efficiency_data.json`。

### 第三步：基于已保存 JSON 生成图表

```bash
python3 <path-to-skill>/scripts/efficiency_chart.py \
  --input efficiency_data.json \
  --output-dir <输出目录> \
  --prefix efficiency
```

脚本会输出生成图片路径。除 PDF 等明确支持图文合并的文件外，分析报告正文不嵌入图片路径；常规聊天应先将生成的图片作为独立附件/图片消息发送给用户，再发送文字分析报告。

### 第四步：解析与分析

1. **读取已保存 JSON**：从 `efficiency_data.json` 解析数据，记录原始数据文件路径
2. **按汇总类型分组**：将数据按 `汇总类型` 字段分为大部门汇总和部门汇总两组
3. **效率评估**：分析各大部门/部门的效率水平
4. **趋势分析**：如有多日数据，分析效率变化趋势
5. **对比分析**：跨部门、跨日期对比效率差异
6. **识别异常**：找出效率异常偏高或偏低的记录
7. **发送图表和输出报告**：常规聊天先将 `efficiency_chart.py` 生成的图片作为独立图片发送给用户，再以结构化方式输出文字分析报告，并在报告中明确标注分析基准时间

## 分析维度

### 大部门效率评估

- 先查看大部门汇总数据，了解成衣一部/二部/三部的整体效率水平
- **效率水平判断**：
  - 效率 ≥ 100%：超高效，产出超过投入时间
  - 效率 80%-100%：正常高效范围
  - 效率 60%-80%：中等效率，有提升空间
  - 效率 < 60%：效率偏低，需关注原因

### 部门级效率对比

- 查看部门汇总数据，在同一汇总类型下对比各部门效率
- 同一大部门内各部门效率对比
- 不同大部门之间的效率对比
- 识别效率标杆部门和效率洼地

### 人数与产能分析

- 结合 `人数` 字段分析人均产出
- 人数多但效率低的部门可能管理或排产存在问题
- 人数少但效率高的部门可作为标杆

### 趋势分析

- 多日数据时，观察效率变化趋势：
  - 持续上升：产能逐步释放
  - 波动较大：生产不稳定
  - 持续下降：可能存在效率损失因素

### 员工效率分析（明细模式）

- 部门内员工效率排名
- 识别高效率/低效率员工
- 关注产出标准工时为空的记录（可能未参与计件或数据缺失）

### 隐患识别

#### 效率异常偏高
- 效率远超 100%：可能标准工时设定过低，或数据录入异常
- 某部门效率突然跳升：需核实数据准确性

#### 效率偏低
- 效率持续低于 60%：可能存在产能浪费、停工待料、设备故障等问题
- 某部门效率明显低于同大部门其他部门：管理或排产问题

#### 数据缺失
- 产出标准工时为空：该记录不参与效率计算，大量空值可能影响整体评估
- 上班时间为 0 或空：数据异常

#### 部门间失衡
- 同一大部门内效率差异过大：可能存在资源分配不均
- 某些部门长期效率偏低：需关注排产合理性

## 柱状图生成脚本

效率分析模块提供柱状图自动生成脚本 `efficiency_chart.py`，用于将汇总数据可视化为对比柱状图。

### 脚本位置

```
<path-to-skill>/scripts/efficiency_chart.py
```

### 生成图表类型

脚本会自动生成 **1 张组合柱状图**，从上到下依次包含：

1. **大部门对比柱状图**：X 轴为大部门，每组柱子为不同日期。便于直观对比同一部门在不同日期的效率变化，以及不同部门之间的效率差异。
2. **成衣一部部门级对比柱状图**：X 轴为具体部门，每组柱子为不同日期。
3. **成衣二部部门级对比柱状图**：X 轴为具体部门，每组柱子为不同日期。
4. **成衣三部部门级对比柱状图**：X 轴为具体部门，每组柱子为不同日期。

部门名称按中文自然排序（一组 < 二组 < ... < 十组）。

### 使用方法

```bash
# 1) 先调用 order_efficiency 工具取数，并将返回的 JSON 原样写入 efficiency_data.json
#    （汇总查询一次即可，供报告分析和图表生成共同使用）

# 2) 使用同一份 JSON 文件生成组合图表
python3 <path-to-skill>/scripts/efficiency_chart.py \
  --input efficiency_data.json \
  --output-dir <输出目录> \
  --prefix efficiency
```

### 参数说明

| 参数 | 缩写 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `--input` | `-i` | ❌ | stdin | 输入 JSON 文件路径，不指定则从标准输入读取 |
| `--output-dir` | `-o` | ✅ | - | 图片输出目录路径 |
| `--prefix` | `-p` | ❌ | efficiency | 输出文件名前缀 |
| `--dpi` | - | ❌ | 150 | 图片分辨率 |

### 输出格式

脚本执行后输出 JSON 格式的结果，包含组合图片路径和内容描述：

```json
{
  "generated_charts": 1,
  "charts": [
    {
      "chart_type": "组合对比",
      "file_path": "/output/efficiency_combined.png",
      "description": "生产效率组合柱状图，依次包含大部门、成衣一部、成衣二部、成衣三部"
    }
  ]
}
```

### 图表特性

- **中文支持**：使用中文字体配置，中文标题和标签正常显示
- **组合输出**：大部门、成衣一部、成衣二部、成衣三部合并在同一张纵向图片中
- **100% 基准线**：所有子图包含灰色虚线标注 100% 效率基准
- **数据标注**：柱顶标注效率百分比，大部门子图同时标注人数
- **部门排序**：大部门和部门名称按中文数字自然排序（一部、二部、三部；一组、二组...十组、十一组...）
- **X 轴为部门，柱子为日期**：方便对比同一部门不同日期的效率变化，以及不同部门之间的效率差异
- **自适应尺寸**：根据部门数量和日期天数自动调整图表宽高

### 调用约定

- 输出目录 `--output-dir` 由调用方（大模型）按系统规则传入，脚本不硬编码路径
- 脚本接受工具返回的原始 JSON（含 `data` 字段的对象或直接数组）
- 生产效率分析默认流程必须先将 `order_efficiency` 工具返回的汇总数据写入一份 JSON 文件，再复用同一份 JSON 做报告分析和图表生成
- 输出给用户时，文字分析报告和 `efficiency_chart.py` 生成的组合图片应分开发送；常规聊天先发送图片、再发送报告，避免报告结束后漏发图表；除 PDF/文档文件外，不要把图片路径或 Markdown 图片链接嵌入报告正文
- 后续如有生产效率柱状图需求，可直接调用此脚本，无需重复编写生成代码，也无需重复查询相同数据
